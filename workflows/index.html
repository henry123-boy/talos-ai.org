Workflows

How we build with coding agents.

Each of us works in one agent conversation. The agent on the laptop plans and decides, cheaper models take the work that can be checked, outposts run the heavy jobs on remote GPUs, and a session can be handed to a teammate who carries on where it stopped. Below is the loop, then one page for each tool we built for it.

The loop

One conversation is the brain. Everything else is a worker or an outpost.

The main agent runs on Claude, on the laptop of whoever is driving. It reads the code, writes the plan and reviews every result. Cheaper models only take tasks with a clear check, and remote machines only execute. Choose a step to see where it happens.

How we work

Plan first
Every task starts as one plan file that the agent keeps current. A person approves it before work starts and reads it again before anything ships.
Parallel, then review
Independent changes run as subagents in separate git worktrees. The main agent reviews each one and merges them in a fixed order. talos-sky 0.4 shipped this way.
Cheap work, checked
Workers get well-specified tasks with a clear done check, such as tests that must pass or citations to spot-check. Claude reviews what comes back before anyone relies on it.
Rent small, return fast
The cheapest GPU that fits the job, rented only after a person confirms the offer, and destroyed when the job is done.
Ask before it leaves
Pushes, deploys, rentals and anything sent outside the machine are confirmed by a person, every time.
Tools for people too
Every command has help and examples, every error says what to do next, and every agent action has a terminal equivalent.
