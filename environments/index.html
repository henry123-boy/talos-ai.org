Environments

Environments where agents design, build and test.

Talos builds RL environments, trajectories and evals for teams training frontier agents on engineering, manufacturing and science. Every task has a brief written by an engineer, a sandbox with the tools of the trade, and a verifier the agent never sees: a solver in simulation, or a test rig in our own factory.

What we build

Engineering
CAD and CAE tasks from real briefs: model the part, mesh it, run the solver, report the numbers or change the design. Graded by running the solver on what the agent submits and checking every requirement.
Manufacturing
Tasks where the agent's design is built in our factory, printed, machined or assembled, then measured on a test rig. The measurement is the reward.
Science
Research problems with simulated instruments and measurement budgets, from Hamiltonian learning to quantum error correction, scored against a private ground truth.
Trajectories
Complete agent runs on every task, from the first command to the final design, with the verifier's result attached.

One episode

The agent designs. The solver, or the factory, decides.

An episode runs the agent's design through the same loop an engineer would: draw it, simulate it, and where a solver is not enough, build it and test it. The verifier's result is the reward.

  1. 01 · in simulationDesignThe agent reads the brief and builds the part in CAD, or routes the board, or writes the simulation.
  2. 02 · in simulationSimulateIt runs the solver on its own design, FEA, CFD, a field solver or dynamics, and iterates before it submits.
  3. 03 · in our factoryManufactureFor factory tasks, the submitted design is printed, machined or assembled, from the agent's files.
  4. 04 · in our factoryTestThe part goes on a rig: a dyno, a flying probe, a load frame, a spin rig. The measurement is compared with the brief.
  5. ↺RewardA number from the verifier, never from an LLM judge, and never from the agent's own report.

How tasks are graded

  • Every task pins its environment and runs its verifier in a separate container without network access.
  • Simulation tasks: the agent's design goes through the solver and every requirement is checked, such as mass, stress, clearances, impedance.
  • Factory tasks: the measurement from the test rig is checked against the same requirements.
  • Science tasks: scored from evidence the verifier checks itself, such as instrument logs and measurement budgets.
  • No LLM judge anywhere in the grading.
  • The reference solution passes every verifier before a task ships.

What a task ships with

Tasks ship in the Harbor format, so they run in any harness that reads it. Trajectories ship as JSON.

instruction.md
The brief: geometry, materials, loads, constraints, and the exact quantities to report.
task.toml
Name, domain, agent timeout, CPU, memory and storage limits, network off, verifier in its own environment.
environment/
The sandbox image: CAD and meshing tools, the solver, Python.
tests/
The verifier, what it grades and the tolerance on each value, with a mesh-convergence study behind the tolerances.
solution/
The reference solution and the solver deck that produced it.
trajectories/
Agent runs on the task, each with its verifier result.
